# Contributing

Thanks for your interest in improving `@thruputchain/client`. Bug reports,
documentation fixes, and code changes are all welcome.

## Before you start

- Search [existing issues](https://github.com/thruputchain/thruput-sdk-ts/issues)
  before opening a new one.
- For anything larger than a small fix, open an issue first so the approach can
  be discussed before you invest time in a pull request.
- Security problems must not be reported through public issues. See
  [SECURITY.md](SECURITY.md).

## Development setup

- Node.js 24 (`.nvmrc`). The published runtime floor is Node 22.12.0.
- npm. `package-lock.json` is the lockfile and CI runs `npm ci`.
- All dependencies install anonymously from the public npm registry:

```sh
npm ci
```

## Verifying changes

Run the same checks CI runs before opening a pull request:

```sh
npm run format:check
npm run docs:check
npm run rpc:check
npm run test:integration-config
npm run typecheck
npm test
npm run build
npm run test:smoke
npm run test:package-boundary
```

`test:smoke` and `test:package-boundary` inspect `dist/`, so run `npm run build`
first. Use `npm run format` to apply Prettier formatting.

Two further checks need the Thruput CLI release pinned in
[`scripts/integration-versions.json`](scripts/integration-versions.json):

- `npm run contracts:check` verifies that the generated contract bindings match
  their pinned specs. Set `THRUPUT_CLI` to the pinned CLI executable.
- `npm run test:integration` builds the package and tests it against a real
  local node (Linux only). See the
  [live integration tests](README.md#live-integration-tests) section of the
  README.

Maintainers run these in CI for every pull request from this repository. If you
cannot run them locally, say so in your pull request and a maintainer will run
them for you.

## Pull request guidelines

- Keep each pull request focused on one change.
- Add or update unit tests under `src/**/*.test.ts` for behavior changes.
- Public API documentation lives in TSDoc comments on the exported symbols.
  Short onboarding guidance goes in `README.md`; `docs/` holds generated
  TypeDoc output only.
- Do not hand-edit generated files. `src/contracts/*.ts`,
  `examples/generated/*.ts`, `src/rpc/generated.ts`, `src/rpc/schema.json`, and
  `specs/native-openrpc.json` are regenerated by the scripts described in
  [AGENTS.md](AGENTS.md).
- Describe what changed and why in the pull request. Reference the issue it
  addresses when there is one.
